# Глава 38. Production: screenshots для App Store

Часть V — финальная. Это **не код**, а методичка «что подготовить
перед первым релизом». Я перечисляю что нужно, какие требования
Apple, и где обычно ошибаются.

Эта глава — про скриншоты.

## 38.1 Зачем скриншоты

После иконки и названия — скриншоты главное, что видит юзер в App
Store. У тебя есть **2-3 секунды**, чтобы убедить юзера тапнуть
«Получить». Скриншоты решают.

Apple просматривает первые **3 скриншота** в листинге без свайпа.
Они должны нести **главное** сообщение твоего приложения.

## 38.2 Требования Apple

Минимум **один** скриншот на каждый обязательный класс устройства.
Сейчас Apple свела требования к двум базовым наборам:

- **6.9"** iPhone (iPhone Air, 17/16/15 Pro Max, 16/15 Plus, 14 Pro
  Max) — обязательно, если приложение работает на iPhone.
- **13"** iPad (iPad Pro M4/M5, iPad Air M2/M3/M4) — обязательно, если
  приложение работает на iPad. Только для iPhone — iPad-скриншоты не
  нужны.

**6.5"** (iPhone 14 Plus, 13/12/11 Pro Max, XS Max) больше **не
обязателен**: его нужно загружать, только если ты НЕ дал 6.9" — иначе
App Store сам масштабирует 6.9" вниз. Старый **5.5"** (iPhone 8 Plus)
из требований убран.

Размеры (точные пиксели, portrait):

- 6.9": **1290 × 2796** (Apple принимает в этом классе и 1320 × 2868)
- 13" iPad: **2064 × 2752**

> ⚠️ Точные размеры зависят от устройства и периодически меняются —
> перед публикацией сверься с актуальной таблицей в App Store Connect
> (Help → Screenshot specifications). Apple требует **ровно** нативное
> разрешение, «почти подходящее» не примет.

Можно загрузить **до 10 скриншотов** на каждый размер (минимум один).
Apple рекомендует 3-5.

## 38.3 Как делать скриншоты

**Симулятор** (рекомендую):

1. Запусти приложение на iPhone 17 Pro Max симуляторе (6.9").
2. Прокрути до нужного экрана.
3. `Cmd+S` — Save Screenshot. Файл `.png` на десктопе.

`xcrun simctl io booted screenshot path.png` — то же самое через
терминал. Удобно для CI.

**Реальное устройство** — менее предсказуемо (статус-бар лезет,
notch в кадре). Если возможно — через симулятор.

**`fastlane snapshot`** — автоматизирует. Записываешь сценарий через
UI test'ы (`XCUITest`), fastlane прогоняет на каждом устройстве,
генерирует скриншоты со всеми текстами на нужном языке.

## 38.4 Стиль скриншотов

Три варианта от плохого к лучшему:

### Плохо: raw screenshot

Просто скрин экрана как есть. Юзер видит обычный список — не понимает,
что там особенного. **Conversion rate низкий.**

### Средне: screenshot + caption

Скрин + большой заголовок сверху или снизу:

```
┌─────────────────────────┐
│  «Все задачи под рукой» │
│                         │
│  [скриншот приложения]  │
└─────────────────────────┘
```

Юзер сразу видит **что это**.

### Хорошо: device frame + caption + background

Скриншот в красивой рамке устройства, на градиентном фоне, с короткой
подписью:

```
┌─────────────────────────┐
│  градиент в брендовых   │
│  цветах                  │
│                         │
│  [iPhone frame со scrn]  │
│                         │
│  «Список дел простой    │
│   как никогда»          │
└─────────────────────────┘
```

Это требует дизайнерской работы, но **conversion** растёт значительно.

Инструменты для создания:
- **AppMockUp Studio** — бесплатно, frames всех iPhone'ов.
- **Figma** — manual, но гибкий.
- **Screenshot Generator** в Xcode (limited).

## 38.5 Что показывать на скриншотах

3-5 главных сценариев:

1. **Главная функция** — то ради чего юзер качает.
2. **Уникальная фича** — что отличает от конкурентов.
3. **Простота** — как легко начать.
4. **Социальное доказательство** — отзывы, число пользователей.
5. **Privacy / трасты** — «без рекламы», «локально», «E2E encryption».

Для Todo например:
1. Список задач с разноцветными ячейками — «Все задачи под рукой».
2. Editor с категориями — «Категории, приоритеты, даты».
3. Главный фильтр — «Сегодня / На неделе / Все».
4. Pull-to-refresh — «Синхронизация».
5. Empty state с CTA — «Создай первую задачу за 5 секунд».

## 38.6 Локализация скриншотов

Если приложение на русском + английском — нужны **обе** версии
скриншотов. iOS App Store позволяет загружать разные screenshots для
разных локалей.

В Xcode Connect:
1. App Store → Screenshots → Edit Localization.
2. Загружай по 5-10 для каждой локали.

Apple **показывает** скриншоты той локали, которая совпадает с
языком устройства юзера. Если нет — fallback на основную (обычно
English).

## 38.7 Видео-preview

Кроме скриншотов, можно загрузить **app preview video** (15-30 сек).

- **6.9"**: 886 × 1920 или 1080 × 1920.
- Формат: `.mov`, `.mp4`, `.m4v`.
- **БЕЗ** звуков system UI, **БЕЗ** finger tap'ов в кадре.
- Не должен начинаться с splash screen.

Делается через QuickTime или `xcrun simctl io booted recordVideo`:

```bash
xcrun simctl io booted recordVideo demo.mov
# ... делаешь действия в симуляторе ...
# Ctrl+C для остановки
```

Видео-preview сильно повышает conversion для **сложных** приложений
(где скриншоты не передают динамику).

## 38.8 Best practices от Apple

Apple каждый год публикует [App Store Product Page guidelines](https://developer.apple.com/app-store/product-page/).

Несколько правил:

- **Не повторяй один и тот же скриншот** на разных позициях.
- **Не используй чужой бренд** (Apple лого, конкурентов).
- **Не используй фразы типа «Best app»** — Apple отказывает.
- **Чёткий текст** — мелкий текст на скрине не читается на small
  device thumbnail'е.

## 38.9 A/B тестирование

iOS 13+ позволяет тестировать разные screenshot-sets для одной версии
приложения через App Store Connect.

Создаёшь 2-4 варианта (different first screenshot, different caption),
Apple показывает разным юзерам, замеряет conversion. Через 1-2 недели
выбираешь победителя.

Особенно полезно для решения «иконка как первый кадр» vs «текст с
описанием».

## 38.10 Где обычно ошибаются

- **Скриншоты с тестовыми данными** — «Тест 1», «Lorem ipsum». Делай
  с **реалистичным** контентом.
- **Скриншоты на старых iOS** — выглядит устаревшим. Снимай на текущем
  iOS.
- **Скриншоты с нотификациями / низким батареем** — берёт «notification
  free» симулятор. Можно сбросить в `Hardware → Time → February 14,
  9:41 AM` (стандарт Apple для marketing-фото).
- **Отсутствие 6.9"** — Apple отклонит submission, если не загрузил
  обязательный размер.

## 📋 Что мы выучили

- **3-5 скриншотов** на каждый размер устройства, минимум **6.9"** для
  iPhone.
- Точные размеры: 1290×2796 (6.9"), 2064×2752 (13" iPad). 6.5" —
  опционально, 5.5" из требований убран.
- **Device frame + caption + gradient bg** — стандарт хороших
  скриншотов.
- Покажи 3-5 главных сценариев, начиная с **главной функции**.
- **Локализация** — отдельные скриншоты для каждого языка.
- **App Preview video** 15-30 сек — для сложных приложений.
- **9:41 AM** — стандартное время в Apple marketing-скриншотах.
- **A/B testing** в App Store Connect для оптимизации conversion.

## Apple Developer Documentation

- [Screenshot specifications](https://developer.apple.com/help/app-store-connect/reference/screenshot-specifications) — точные размеры, форматы и количество скриншотов на каждое устройство.
- [App Store product page](https://developer.apple.com/app-store/product-page/) — рекомендации Apple по оформлению листинга и скриншотов.
- [HIG — App Icons](https://developer.apple.com/design/human-interface-guidelines/app-icons) — параллельно со скриншотами обновляй иконку, требования совпадают.
- [Apple Marketing Resources](https://developer.apple.com/app-store/marketing/guidelines/) — лого, mockup-frames и правила использования бренда в маркетинге.
- [`UIScreen`](https://developer.apple.com/documentation/uikit/uiscreen) — размер экрана и `nativeScale` для предсказуемого рендеринга маркетинговых ассетов.
- [`UIScene`](https://developer.apple.com/documentation/uikit/uiscene) — состояния сцен, важно при автоматизации скриншотов из UI-тестов.
- [`xcrun simctl`](https://developer.apple.com/documentation/xcode/running-your-app-in-simulator-or-on-a-device) — команды для снятия скриншотов и записи видео из симулятора.

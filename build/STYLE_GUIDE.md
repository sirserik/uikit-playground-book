# Style Guide — «UIKit Playground»

Стиль и pipeline согласованы с `ShopApp-Book-Beginner` (yii2-from-scratch /
nuxt4-from-scratch / caravel-board). Эта книга — **каталог-практикум**, в
отличие от линейной beginner-книги.

## Аудитория

Junior–middle iOS-разработчик, который **уже знает Swift и базовый UIKit**,
но хочет научиться делать «полноценные» приложения — со splash, onboarding,
permission primer, auth gate, pull-to-refresh, skeleton, photo viewer и т.д.

Здесь **не объясняем** что такое класс/опционал/массив — это есть в
`ShopApp-Book-Beginner`. Здесь сразу к делу: «вот патерн, вот когда его
применять, вот ошибки которые ловят все».

## Целевая платформа

- **iOS 15.0+** (deployment target учебного проекта `beginner-testing-app`).
- **Xcode 26+** (актуальная 26.4.1).
- Swift с `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor` (Xcode 26 default).
- **UIKit + Storyboard для LaunchScreen, остальное — кодом**. SwiftUI **не используется**.
- Современные API (`@Observable`, `UISheetPresentationController` с custom-detents,
  `actor`-based кэш, async/await) — с явным `@available` или комментарием.

## Локализация

Книга **более универсальная**, чем beginner. По умолчанию — нейтральный
русский. Где нужны конкретные имена/города/валюта — лёгкий казахстанский
контекст (Алматы, тенге, +7 (727)), но без догматичной привязки.

## Структура каждой главы

1. **Заголовок** + 1–2 абзаца контекста («зачем эта глава, какая роль в
   playground'е»).
2. **Что строим** — 1 предложение + ASCII-схема или скриншот.
3. **Подразделы** через `## N.M Название`.
4. **Каждый кусок кода объясняется построчно**. Не «вот 50 строк» — а
   «вот 3, добавили 2, объясняем 6-ю». Эталон — `ShopApp-Book-Beginner`
   глава 1.
5. **Бытовая аналогия** для каждой новой концепции (где уместно).
6. **Упражнение (🛠)** каждые 2–3 раздела, не в конце главы.
7. **«Что мы выучили»** в конце главы — bullet-points.
8. **Ссылка на коммит** в [`uikit-playground-app`](https://github.com/sirserik/uikit-playground-app)
   где этот шаг реализован.

## Особенности этой книги (vs beginner)

- **Каждое mini-app самодостаточно** — главу III.5 «Галерея» можно читать
  без главы III.3 «Калькулятор».
- **Cookbook (часть IV)** — справочник, не учебник. Каждый паттерн = 1
  раздел: «когда применять / минимальный код / частые ошибки / альтернативы».
- **Скриншоты обязательны** для каждого экрана. Складываем в
  `docs/images/<chapter-slug>/<screen>.png`.
- **Production checklist (часть V)** — методический, без кода.

## Avoid AI-обороты

(полный список — в `feedback_writing_style.md` пользователя)

- «Стоит отметить, что» / «Важно понимать, что» / «Как известно,» — выкидываем.
- «На самом деле», «По сути», «В целом» — выкидываем.
- «Прежде всего,» / «В первую очередь,» — выкидываем.
- «Соответственно,» → «Поэтому» или ничего.
- «Таким образом,» → «Итог:» или просто следующее предложение.
- «Иными словами,» → перефраз.
- «Давайте посмотрим / разберёмся» → без «Давайте».
- «следующие/следующего» → «такие/такого» / «то, что».
- Жёсткая bold-структура `**Что**: ...` / `**Решение**: ...` — НЕТ. Прозой.
- Шаблонные вступления «В этой главе мы рассмотрим следующие темы:» — НЕТ.

## Чек-лист перед коммитом главы

- [ ] Все упомянутые API проверены, скомпилированы в `beginner-testing-app`.
- [ ] Скриншоты обновлены, лежат в `docs/images/<chapter-slug>/`.
- [ ] Есть как минимум 1 упражнение (🛠).
- [ ] Есть «Что мы выучили» в конце.
- [ ] Есть ссылка на коммит в companion-app (или пометка «WIP — без кода»).
- [ ] `bash build/build-pdf.sh` собирает книгу без ошибок.
